Data Flow

How a build failure event flows through the system

1

Webhook Received

GitHub sends a CI failure webhook to the Ingestion Service (Go). The event is normalized and published to Redis Streams.

2

Agent Orchestration

The Agent Orchestrator consumes the event from Redis Streams. It invokes the Build Failure Triage workflow via LangGraph.

3

RAG Retrieval

The agent queries the Indexing Service for similar past failures using hybrid search (BM25 from Elasticsearch + vector similarity from Faiss). Results are reranked for relevance.

4

LLM Analysis

Retrieved context + the original log are sent to the Model Service for LLM inference (Qwen via OpenRouter). The model generates root cause analysis and fix recommendations.

5

Response Delivery

Results stream back through the API Gateway via SSE (Server-Sent Events) to the React frontend, where the user sees the diagnosis in real-time.

Kubernetes + ArgoCD GitOps

# Terraform provisions:
# - VPC (2 AZs, public + private subnets)
# - EKS cluster (2x t3.large nodes)
# - ECR repositories (8)
# - IAM OIDC + IRSA roles
# - ALB Ingress Controller
# - ArgoCD (auto-sync + selfHeal)
CI/CD Pipeline: GitHub Actions → Matrix testing (Go ×2, Python ×4, Frontend) → Docker build + ECR push (sha-<commit>) → Kustomize image update → ArgoCD auto-sync.
