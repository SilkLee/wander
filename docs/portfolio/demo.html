Demo 1: Build Failure Triage (RAG)

Submit a CI build failure log and get AI-powered root cause analysis

1

Navigate to Log Analysis Page

Click "Log Analysis" in the sidebar. This page accepts CI build logs for automated triage.

2

Submit a Build Log via API

curl -X POST http://localhost:8000/api/v1/agent/analyze \
  -H "Content-Type: application/json" \
  -d '{
    "log_content": "FAIL: TestDatabaseConnection - connection refused localhost:5432\nError: dial tcp 127.0.0.1:5432: connect: connection refused\npanic: runtime error: invalid memory address",
    "source": "github-actions",
    "repository": "myorg/backend-service",
    "build_id": "run-12345"
  }'
3

AI Response (RAG Pipeline)

The system performs:

  1. Classification — Fine-tuned classifier categorizes the failure type
  2. Retrieval — Hybrid search (BM25 + vector) finds similar past failures
  3. Generation — LLM generates root cause analysis with fix steps
Expected Output:
{
  "analysis": {
    "root_cause": "PostgreSQL connection refused - database service not running or port blocked",
    "severity": "HIGH",
    "category": "infrastructure",
    "fix_steps": ["Verify PostgreSQL service is running", "Check port 5432 availability", "Review Docker Compose health checks"],
    "similar_failures": [...],
    "confidence": 0.92
  }
}
What's happening under the hood: The request flows through Go API Gateway → Agent Orchestrator (LangGraph) → Indexing Service (Faiss + ES hybrid search) → Model Service (Qwen via OpenRouter) → streamed back via SSE.

Demo 3: Code Review Assistant

Automated code review with LLM-powered analysis

1

Navigate to Code Review Page

Click "Code Review" in the sidebar.

2

Submit Code for Review

curl -X POST http://localhost:8000/api/v1/agent/code-review \
  -H "Content-Type: application/json" \
  -d '{
    "diff": "--- a/auth/handler.go\n+++ b/auth/handler.go\n@@ -1,5 +1,10 @@\n+func Login(c *gin.Context) {\n+  password := c.PostForm(\"password\")\n+  if password == \"admin123\" {\n+    token := jwt.New()\n+    c.JSON(200, token)\n+  }\n+}",
    "language": "go",
    "pr_title": "Add login endpoint"
  }'
3

Review Output

Expected Issues Found:
  • CRITICAL: Hardcoded password — use bcrypt hashed comparison
  • HIGH: No error handling for JWT creation
  • MEDIUM: Missing rate limiting on auth endpoint
  • LOW: Use proper HTTP status codes (200 → 201 for creation)

Demo 4: DORA Metrics Dashboard

Engineering efficiency tracking with four key DevOps metrics

1

Navigate to DORA Metrics Page

Click "DORA Metrics" in the sidebar. The dashboard shows four key metrics tracked over time.

2

Record a Deployment Event

curl -X POST http://localhost:8000/api/v1/metrics/events \
  -H "Content-Type: application/json" \
  -d '{
    "event_type": "deployment",
    "repository": "workflow-ai",
    "commit_sha": "abc123",
    "timestamp": "2026-03-15T10:30:00Z",
    "success": true,
    "duration_seconds": 180
  }'
3

View DORA Metrics

curl http://localhost:8000/api/v1/metrics/dora?period=weekly
Four DORA Metrics:
Deployment Frequency
How often code is deployed to production
Lead Time for Changes
Time from commit to production deploy
Change Failure Rate
Percentage of deployments causing failures
Mean Time to Recovery
Time to restore service after an incident
Impact: Automated failure triage reduces MTTR from 45 min (manual) to 8 min (AI-assisted) — a 5.6× improvement quantifiable in the DORA dashboard.

Demo 5: Incident Response (Multi-Agent)

LangGraph multi-agent workflow for automated incident triage

1

Navigate to Incident Response Page

Click "Incident Response" in the sidebar.

2

Submit an Incident

curl -X POST http://localhost:8000/api/v1/agent/incident \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Database connection pool exhaustion",
    "description": "PostgreSQL max connections reached. API returning 503 errors. Affected: payment-service, order-service.",
    "severity": "P1",
    "affected_services": ["payment-service", "order-service"],
    "error_logs": "FATAL: too many connections for role \"app_user\"\nremaining connection slots reserved for superuser"
  }'
3

Multi-Agent Response

The LangGraph orchestrator spawns multiple specialized agents:

Triage Agent

Classifies severity, identifies blast radius, assigns priority

Diagnosis Agent

Analyzes error logs, queries historical incidents, identifies root cause

Resolution Agent

Generates runbook steps, suggests immediate mitigations, recommends long-term fixes

Communication Agent

Drafts stakeholder updates, creates incident timeline, prepares postmortem template
