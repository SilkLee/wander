Key Design Decisions

Why we chose each tool and pattern — with rationale for every tradeoff

Native GitHub integration: OIDC federation, workflow_run chaining, path-filter actions — all first-party.
Zero infrastructure: No Jenkins server to maintain, patch, or scale.
Matrix strategy: 15 parallel jobs scale automatically with GitHub-hosted runners.
Cost: Free for public repos — ideal for a portfolio project.
Web UI: Built-in dashboard for sync status visualization — critical for debugging.
App-of-apps: Hierarchical application management (root → workloads + policies).
selfHeal: Automatic drift detection and correction. kubectl patch gets reverted within seconds.
Kustomize native: No plugins needed for our manifest strategy.
Traceability: Every running image maps to exactly one git commit.
No ambiguity: :latest or :v1.2.3 can be overwritten; sha-abc123 cannot.
Rollback: Point to any previous SHA — no version ordering needed.
CI/CD simplicity: Tag = commit SHA — no version bump logic, no release workflow.
The CD pipeline commits updated kustomize tags back to main. Without [skip ci], this triggers another CI run → another CD run → infinite loop. The [skip ci] marker breaks the cycle cleanly.
A deploy in progress must complete. Half-pushed images or partial kustomize updates leave the system in an inconsistent state. CI can be cancelled freely (newer code supersedes), but CD cannot. This is a deliberate asymmetry.
Shift-left: Non-compliant manifests are caught before they reach the cluster, not after.
Pre-verified compliance: All 13 running pods already comply with all 6 policies — verified before enabling Enforce mode.
CI/CD safety net: Even if a developer bypasses code review, Kyverno blocks non-compliant deployments at admission time.
Scoped blast radius: Policies target workflowai namespace only — kube-system, argocd, monitoring, kyverno namespaces are unaffected.

Operational Runbook

Quick-reference commands for day-to-day operations and troubleshooting

🔍 Check CI Status

# Latest runs
gh run list --limit 5

# Watch a specific run
gh run watch <run-id> --exit-status

# View failed job logs
gh run view <run-id> --log-failed

🚀 Check Deployment

# Pod status
kubectl get pods -n workflowai

# Rollout status
kubectl rollout status deployment/api-gateway -n workflowai

# ArgoCD app status
kubectl get applications -n argocd

⏲ Current Image Tags

kubectl get deployment -n workflowai \
  -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.template.spec.containers[0].image}{"\n"}{end}'

↺ Rollback

# Revert to previous SHA tag
cd k8s/overlays/production
kustomize edit set image \
  "<ECR>/workflowai/<svc>=<ECR>/workflowai/<svc>:sha-<prev>"
git commit -m "rollback: <svc> to sha-<prev>"
git push  # ArgoCD auto-syncs

Troubleshooting Guide

SymptomDiagnosisFix
CI fails on Python pip install logs — PyTorch index? Verify --extra-index-url for CPU wheels
CD skipped entirely CI didn’t succeed, or no changes on main Check workflow_run trigger condition
Images not pushed to ECR OIDC role trust policy mismatch Verify GitHub OIDC provider in IAM
ArgoCD out of sync Manual kubectl change reverted by selfHeal Commit change to git instead
Pod CrashLoopBackOff Missing secret or config kubectl logs <pod> -n workflowai
ALB 404 Ingress path not matching Check k8s/overlays/production/ingress.yaml
[skip ci] not working Commit message format wrong Ensure exact [skip ci] in message body
Key Operational Insight: selfHeal: true means git is the only way to change cluster state. Direct kubectl patch on ConfigMaps or Deployments gets reverted within seconds. All changes must flow through: Code change → git commit → git push → ArgoCD detects → sync.
